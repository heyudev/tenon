# 榫 · Tenon

AI 小说创作系统。**一套方法论工作台：把「我想写本书」推到「能写、写得下去、写得完」。**

它不替你想创意，也不规定创意从哪来——画面、人物、设定、类型都能进。
它负责的是：验证你手上的东西撑不撑得起长篇，然后把它拆成每天能写的活。

一台自立的机器：资产层、项目层、方法论层全部在这个仓库和本地数据库里，不读取、不依赖任何外部目录。

## 跑起来

```bash
npm install
npm run seed        # 建库并导入资产层
npm run dev
```

打开 http://localhost:3100。数据在 `data/tenon.db`（本地 SQLite，不进仓库）。

## AI 后端（可切换）

在「设置」里三选一，随时切：

| 后端 | 说明 |
|---|---|
| **Claude CLI**（默认） | 调本机 `claude` 命令，复用已登录的订阅，不需要 API key |
| Anthropic API | 直接调 Messages API，需要 `.env.local` 里的 `ANTHROPIC_API_KEY` |
| Codex CLI | 调本机 `codex`，作为备用后端 / 交叉验证 |

每个 AI 动作旁边都有一个 `⧉`：只把装配好的提示词复制到剪贴板，拿去任何地方跑。
**后端不可用不会挡住任何工作流。**

## 管线 · 10 层 46 环节

```
作者  能力盘 · 素材库 · 拆书库 · 复用资产库 · 产能排期        ← 跨书常驻，永不挡路
立项  市场赛道 → 类型与读者契约 → 核心创意成型 → 卖点与立项 → 投放物料
      （核心创意成型不限来源：画面／人物／设定／类型都从这里进，出来时必须站着一个人）
世界  资源系统 · 力量体系 · 金手指专项 · 地理与势力 · 历史时间线 · 世界观圣经
人物  主角 · 反派体系 · 配角群像 · 关系网与情感线 · 人物声音与对话
叙事  视角与人称 · 文风与语感 · 叙事结构与多线 · 开篇方案竞选     ← 决定"怎么讲"，动笔前定死
结构  总纲四层揭露 → 卷纲 → 悬念账本 → 事件线与爽点排期 → 高潮设计 → 场景设计
生产  brief → 正文 → 人工润色 → 审校门禁 → 状态回写 → 存稿排期    ← 日更主循环
运营  发布准备 → 数据看板 → 诊断调整 → 读者反馈 → 卷末复盘
收尾  完结收束 → 完本复盘与 IP 派生
协议  卡文救火 · 风险合规扫描                                    ← 随时可触发
```

**地图是全的，路是裁出来的。** 平台 × 频道 × 类型三个参数决定这本书哪些环节必经、哪些是增强、哪些用不上。
左轨顶部有条「最小可动笔集合」进度线——7 项齐了就能写第一章，不必等全部环节填完。

开新书先做**入口分诊**：什么都没有 / 有一个画面 / 有一条设定 / 想写某个类型 / 有本卡住的书 / 完本要开下一本，
六种起点各走各的路，最后都汇到同一关：**卖点与立项**——不管创意从哪来，都要过评分卡和排雷清单。

每个环节都说清五件事：**不做会死在哪里 · 具体怎么做 · 做到什么算够 · 最容易怎么做砸 · 产出什么**。

门禁分两类：**可判定项由系统从数据里算**（最大爽点间隔、字数区间、钩子同型、评分卡总分、伏笔逾期…共 37 条），
人勾不动也不用勾，不通过时会告诉你为什么；剩下的是只有人能判的主观项（够不够狠、愿不愿意点下一章）。

## 资产层（跨书共享）

`seed/assets.json` 是这一层的种子，系统自有 schema，`npm run seed` 幂等重建。

- **平台库** —— 番茄／起点的完整差异：收入结算、开书到上架、内容规范、流量分发、数据后台、运营动作、风险。
  结构性机制直接给；分成比例、全勤、签约门槛这类会变的数值只标出「你要去查什么」，查完自己填并记核实日期。
- **方法论库** —— 59 张卡：公理、技法、平台硬约束、四道关口清单、委员会七角色。
  每张卡都是可执行判据（阈值 / 决策流程 / 失效模式），写不成判据的不进这一层。
  它们同时是界面上的门禁依据和提示词里注入的约束。
- **核心资源参考** —— 14 种资源的五要素（源头 / 路径 / 沉淀 / 黑市 / 类比），建资源系统时当参照。

> 规则库 / 概念图谱 / 组合实验室已退役——那套「改一条现实规则→推演出文明」的上游把一家之言
> 做成了所有人的必经路，与"帮任何人写完一本书"的定位冲突。退役前的快照留在
> `archive/rule-engine-snapshot.json`，不被 seed 读取。

## 把已有的书接进来

```bash
npm run import -- "<项目目录>" --venue qidian --dry   # 先看提取结果
npm run import -- "<项目目录>" --venue qidian          # 落库
```

目录必须显式给出，系统不预设任何位置。提取是一次性的——跑完之后书完全活在 `data/tenon.db` 里，
与来源目录再无关系。

**默认只提取大纲层**：卷号／章号／章标题、章节摘要、伏笔账本、人物档案。
正文文件只用来定位卷章，**章的正文字段一律留空——那是留给作者的位置**。
确实要把既有正文一并搬进来，显式加 `--with-body`。

提取按可靠度分层：卷与章目录、章节摘要（目录约定明确，可靠）、伏笔与人物（尽力而为）。
**解析不出来的字段留空并在报告里说明，不猜着往真相源里填。**

**导出**：作品页右上角「导出」→ `export/<书名>/` 的 markdown 快照
（导航 / 立项书 / 世界观圣经 / 人物档案 / 伏笔总账 / 卷结构 / 章节记录 / 正文 / 数据）。
结构化数据是真相源，导出物只是快照，改快照不会回流。

## 设计原则

- **人做高杠杆低频决策，AI 做高工作量高频执行。** AI 负责"对"，人负责"过分"。
- **AI 产出不自动进真相源。** 状态库写错一次，错误会在后续生成里自我复制——所以必须过人眼。
- **正文永不回读。** 写第 200 章时读的是状态文件，不是前 199 章。分层记忆 L0–L4 按需注入。
- **门禁是硬的。** 一票否决项不勾满，环节永远不算通过。
- **系统自立。** 不读外部目录、不留外部路径、不镜像别处的内容。
